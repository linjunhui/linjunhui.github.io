# Harness：大模型 Agent 的工程底座

## 一、核心定义

**Agent = 大模型 + Harness**

- **大模型（Model）**：Agent 的大脑，负责理解目标、做出决策。
- **Harness**：去掉大模型后剩余的全部支撑系统，负责调度与管控 Agent 的整个工作流程，保证大模型稳定、可靠地执行任务。

> 传统聊天机器人只能思考，无法操作外部工具、自主完成任务；Agent 的差异在于能独立做事，而 Harness 正是实现这一能力的工程系统。

## 二、核心组成模块

| 模块 | 作用 |
|------|------|
| 记忆系统 | 保存历史交互信息，为模型提供上下文 |
| 工具 | Agent 的手脚，将模型决策转化为真实动作（读文件、调用接口等） |
| 规则 | 行为准则，规定能做什么、不能做什么，定义输出标准 |
| 任务循环控制器 | Harness 的核心，统一调度各模块，决定循环继续或终止（思考→行动→检查） |
| 可扩展模块 | 按需新增，无固定组件清单，如上下文管理（从全量记忆中筛选当前任务相关信息打包送入模型，减少上下文浪费与信息干扰） |

## 三、运行流程（以代码审查 Agent 为例）

1. **组装上下文**：Agent 接收任务后，Harness 将系统提示词、用户指令、规则、筛选后的历史记忆组装为完整上下文，发给大模型。
2. **执行工具**：大模型返回工具调用指令，Harness 执行对应工具操作。
3. **循环迭代**：工具结果追加到上下文，再次提交大模型，进入新一轮思考，反复循环。
4. **输出结论**：直到大模型不再请求工具、直接输出最终结论，Harness 捕获并整理结果，任务结束。

## 四、DeepSeek Harness 的四种工作模式

- **标准模式**：内置丰富工具，支持 shell、文件编辑、网页检索。
- **ETC 模式**：使用 TypeScript 代码完成多步工具调用。
- **极简模式**：仅保留 shell、文件编辑，环境轻量化。
- **自定义 Agent 模式**：可自主定义工具权限、业务规则，创建专属 Agent（即视频演示所用模式）。

## 五、核心观点

大模型的能力上限决定 Agent 的潜力；**Harness 的工程质量决定这份潜力能否稳定落地**。模型再强，若缺少一套可靠的调度系统，在真实场景下依然容易出错、失控。
