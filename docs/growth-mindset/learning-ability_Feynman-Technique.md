## Mindset 001｜Feynman Technique — Explained in English

**The core idea in one sentence**: *"If you can't explain something in simple terms, you don't really understand it."* Learning is best done not by memorizing, but by **teaching others**. Named after physicist Richard Feynman, it forces you to **actively process information** (rather than passively memorize) and rebuild knowledge in your own words.

### What each step does

| Step | Action | Key question |
| --- | --- | --- |
| **1 Set the goal** | Choose the topic; define Why/How/What | What am I learning? Why? How? |
| **2 Output / Teach** | Write it + say it | Can I explain it in plain language? |
| **3 Simplify** | Chunk knowledge, build a model, form a system | If I can't explain it, do I really understand it? |
| **4 Review** | Omission → re-memorize; error → re-learn; insight → re-connect | Is there anything I keep failing to explain? |

### Why it works

- **Forces active processing**: Output exposes gaps far better than input — teaching instantly surfaces the details you haven't really understood.
- **Feedback loop**: every stumble becomes the starting point of the next round, instead of endless rote memorization.
- **From "knowing" to "able to teach"**: the real test of mastery is being able to teach a complete beginner.

### The example from the book (Product Manager Xiao Wang learning data analysis)

1. **Set the goal**: Why – master data analysis / How – courses·reading·practice·output / What – basic concepts, tools (Excel, SQL), methods & cases
2. **Simplify**: chunk the knowledge (basics / tools / methods / practice), build a mind map
3. **Output**: write a short summary, explain it to people around
4. **Review**: find omissions → fix errors → connect new knowledge

**Remember it in one line**: *To learn anything, teach it — until you can explain it clearly, you haven't truly learned it.*
